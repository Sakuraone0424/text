## 实现范围

- `training.js`：身份确认和缓存恢复解耦。启动先确认用户，独立查询已有缓存对应的试卷；身份成功不表示试卷可达。身份网络异常或试卷可恢复网络故障时，恢复受用户名、存储key、paper_id、原始开始/截止时间、版本及结构约束的本机缓存。
- API使用`cache:no-store`。不依赖`navigator.onLine`决定试卷是否可用；恢复联网事件与原15秒轮询都会重新确认身份、试卷状态、deadline和版本，再走原flush、照片队列和409机制。离线暂存不被标记为服务端已同步。
- 401/403锁定并保留有效缓存，重新认证/试卷确认前不回退可编辑模式；账号切换和绑定不匹配时不载入旧账户草稿；无效缓存保留但不编辑。
- 未开始仍只显示须知；已提交保持只读。服务端已提交后，未确认的本机pending保留供核查，但不再上传计入成绩。原计时前无效预答清理保留。
- 恢复文字、待同步文字及图片ID；IndexedDB照片保留。照片按用户、试卷及开始时间筛选，继续使用供应商无关的原数据库SHA去重，没有新增上传接口。
- 使用原服务端deadline和performance锚点；同一考试估算时间不向后移动。离线到期后输入和标记只读，不能保存迟到输入；联网后由原服务端门禁确定实际入卷答案。
- `training-ui.js`：显示待核验状态和到期只读状态。`training-sw.js`缓存升级为`v7-offline-recovery`，仍只缓存静态资源，不缓存API、答案或rubric。
- 没有新API、数据库迁移、鉴权绕过、Secure Cookie降级、计时规则或判分规则变化。

## 新增20项HTTPS回归

运行：`cd backend && TEST_DATABASE_URL=<独立本地测试库> python -m pytest tests/test_https_recovery.py -q`。

- Chromium、Firefox、WebKit各自真实HTTPS登录、准备/开始、离线刷新文字恢复、重新同步及数据库读回。
- Firefox身份返回200但试卷请求不可用，以及身份请求网络失败；同时保持`navigator.onLine=true`模拟部分网络故障，仍必须标记待确认，不盲目写入。
- 身份接口与试卷接口各自的401/403，包含拒绝后再次网络失败仍不得解锁的情况。
- 不同用户key、缓存绑定用户名不符、损坏JSON、无效版本、被延长的缓存截止时间。
- 未开始和已提交缓存离线刷新不得显示可编辑题目。
- 运行中切换身份，不混用或覆盖旧账户缓存。
- 离线重载后服务器已有新版本，保持409冲突，不覆盖较新答案。
- 照片请求已落库但收据丢失，IndexedDB保留；离线再选照片、重载、恢复联网，数据库实际图片字节的SHA重算一致，图片和引用均无重复。
- 离线跨过截止时间并重载，保留原deadline与有效草稿；迟到输入不能写入成绩。

鉴权、协议故障及丢收据采用明确标注的传输故障注入，其余调用为实际HTTPS和PostgreSQL；不是合成AI审核或模型调用。到期测试仅把一次性QA记录设置为接近截止，同时保持`deadline-started_at=3600秒`，不改系统时间或正式数据。
